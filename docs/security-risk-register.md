# Security Risk Register

Audit snapshot: 2026-10-13. `npm audit --json` reported 0 critical, 21 high, and 10 moderate
advisories. `npm audit --omit=dev` reported the same totals because Expo CLI/Metro dependencies are
included by the mobile workspace dependency graph. No finding in the snapshot targets the Nest/Express
request handlers, JWT auth, Next server, or the current note/checklist evidence route.

| Package or path                                              | Severity                  | Exposure in this slice                                                                  | Current impact                                                                                                                                               | Planned action                                                                                                          |
| ------------------------------------------------------------ | ------------------------- | --------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------- |
| Expo CLI, Metro, `braces`, `micromatch`, `node-forge`        | High                      | Expo development/build/signing toolchain; not used by API request handlers              | Local app bundling and native project tooling                                                                                                                | Re-evaluate with the Expo SDK upgrade before public release; do not force an SDK downgrade to clear audit output        |
| React Native CLI/Metro dependency graph                      | High                      | Mobile app build/runtime dependency graph; reported path is primarily CLI/Metro tooling | Build tooling and local bundling; no server-side HTTP exposure                                                                                               | Upgrade within the Expo-supported version matrix and verify an Android export before deployment                         |
| Prisma CLI, `@prisma/config`, `deepmerge-ts`                 | High                      | Schema/migration development tooling                                                    | Prisma CLI configuration, not generated Prisma query execution                                                                                               | Upgrade Prisma tooling deliberately and rerun migration/seed tests before deployment                                    |
| `expo-router` -> `query-string` -> `decode-uri-component`    | Moderate                  | Mobile deep-link/query parsing                                                          | Malformed percent-encoded route input may cause excessive decoding work; current app uses internal typed routes and no externally supplied deep-link payload | Avoid parsing untrusted external links; update Expo Router with a compatible SDK upgrade before enabling external links |
| Multer 2.4.0 / Busboy 1.6.0 under `@nestjs/platform-express` | No advisory in this audit | Installed transitively; no upload route invokes it                                      | No evidence upload path is enabled                                                                                                                           | Keep binary uploads disabled; re-audit before adding file handling and add size/MIME/storage controls                   |

The non-breaking `npm audit fix` attempt failed dependency resolution. Do not use `--force` as a
blanket fix; it proposed incompatible Expo/React Native major downgrades. Re-run the audit before
public deployment, external auth integration, or enabling media uploads.
